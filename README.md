# 캐릭터 이동 및 뷰포트 제한

Python과 pico2d로 구현한 단일 파일 데모이다. 개발 기준은 [PRD_dev.md](PRD_dev.md)이다.

## 실행

```powershell
python -m pip install pico2d
python character_move_viewport.py
```

방향키로 이동하고 ESC 또는 창 닫기로 종료한다. 상하 이동은 직전 좌우 방향을 유지한다. 반대 방향 입력은 상쇄되고 대각선 이동은 직선과 같은 속도이다. 경계에서 바깥쪽 키를 누르면 위치는 고정되지만 RUN 애니메이션은 계속된다. 모든 이동 입력을 해제하면 IDLE 애니메이션으로 전환한다.

`TUK_GROUND.png`와 `animation_sheet.png`는 실행 파일과 같은 폴더에 둔다. 다른 작업 디렉터리에서 실행해도 파일 위치를 기준으로 로드한다. 화면은 1280 × 1024 px, 캐릭터 출력 크기는 100 × 100 px, 이동 속도는 300 px/s이다. 기본값은 실행 파일 상단의 상수로 관리한다.

## 자체 검증

```powershell
python character_move_viewport.py --self-test
```

창을 열지 않고 정지 위치, 네 방향 이동 거리, 대각선 속도, 네 모서리, 초과 이동 제한, 시간 분할에 따른 거리 일치를 assert로 검증한다. pico2d 설치 없이도 실행할 수 있다. assert를 비활성화하는 `python -O`는 검증에 사용하지 않는다.

## 개발 및 검증 결과

검증일은 2026-10-07이다. 사용 환경은 Windows, Python 3.13.15, pico2d 1.5.1이다.

- 001~021: 명세의 구현 단계를 순서대로 변경하고 컴파일, import, 이벤트 루프 및 단계별 동작 검증 후 커밋했다.
- 022: PowerShell 파이프의 한글 인코딩 문제로 손상된 코드 안내문을 복구했다. 001~021 커밋의 메시지도 복구했으며 각 커밋의 코드 변경은 유지했다.
- 023: 실행법과 검증 결과를 기록했다. 총 23개 개발 커밋이며 번호, 주요내용 두 글자, `_` 구분 양식을 사용했다.
- 자체 검증과 `python -S character_move_viewport.py --self-test`가 통과했다. 긴 경과 시간은 0.05초로 제한되어 한 번에 15 px 이하로 이동함을 별도로 확인했다.
- 실제 Windows SDL 렌더러의 숨겨진 창에서 552프레임 통합 검증이 통과했다. SDL 이벤트 큐에 키 누름·해제·종료 이벤트를 주입하고 실제 이미지를 렌더링했다.
- 실제 렌더링 캡처를 시각 확인했다. 배경 전체와 중앙 캐릭터, 왼쪽 위 경계, 네 행의 32개 프레임이 정상 출력됐다. 인접 프레임 혼입이나 캐릭터 잘림이 없어 추출 원점 보정은 필요하지 않았다.
- 리소스 누락 시 파일명·경로 안내, 로드 오류 시 창 정리와 예외 보존, ESC/QUIT 이후 추가 렌더링 방지가 통과했다.
- import만으로 창이 열리지 않으며 다른 작업 디렉터리에서도 실제 리소스 로드가 성공했다.

위 결과는 자동 이벤트 주입과 렌더링 캡처 확인에 기반한다. 사람이 표시된 창에서 물리 키보드와 닫기 버튼으로 수행하는 수동 T01~T18 검증은 미실시이다. 명세의 수동 인수 절차 전체가 완료되었다고 표시하지 않는다.

검증 환경에서는 오디오 장치 경고가 출력됐지만 이미지와 이벤트 처리는 정상 동작했다. 게임은 오디오 기능을 사용하지 않는다. SDL dummy 비디오 드라이버에서는 설치된 pico2d의 렌더러 생성이 실패하여 Windows 렌더러로 검증했다.
